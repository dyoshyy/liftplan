# 実装中の自己判断ログ

実装計画に書かれていなかった、あるいは計画と異なる判断をした箇所と、その根拠。
判断が割れうるものは別エージェントに客観評価させ、その結果も記録する。

---

## D-001: Go のバージョンを 1.23 ではなく 1.26.3 にした

**計画の記述:** Go 1.23

**実際:** 1.26.3

**根拠:** 開発機の mise に 1.23 が入っておらず、`mise use -g go@1.26.3` が提示された。計画が 1.23 を指定した理由は「`net/http` のメソッド付きパターンマッチ（1.22 以降）が使えること」であり、1.26.3 はこれを満たす。より新しいバージョンを避ける理由が無いため、環境にあるものを採用した。`mise.toml` をリポジトリにコミットし、バージョンを固定している。

**影響範囲:** なし。標準ライブラリのみを使うため、互換性の懸念は無い。

---

## D-002: 依存方向テストの許可リストに `context` と `sync` を最初から入れた

**計画の記述:** Task 1 では最小の許可リストとし、`context` は Task 19 で追加する

**実際:** 最初から `context` と `sync` を含めた

**根拠:** 許可リストを小刻みに広げても守られる不変条件は変わらず、PR ごとにテストファイルを触る差分ノイズが増えるだけ。`context` はリポジトリインターフェースで必須になることが計画時点で確定しており、`sync` はテストの並行検証で使う。どちらも「外部への依存」ではなく、ドメイン層が外側を知らないという本来の制約には影響しない。

**影響範囲:** 検査の厳密さは変わらない。外部モジュール（ホスト名を含む import）と、自リポジトリの domain 外パッケージは引き続き弾かれる。
