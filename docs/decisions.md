# 実装中の自己判断ログ

実装計画に書かれていなかった、あるいは計画と異なる判断をした箇所と、その根拠。
判断が割れうるものは別エージェントに客観評価させ、その結果も記録する。

---

## D-001: Go のバージョンを 1.23 ではなく 1.26.3 にした

**計画の記述:** Go 1.23

**実際:** 1.26.3

**根拠:** 開発機の mise に 1.23 が入っておらず、`mise use -g go@1.26.3` が提示された。計画が 1.23 を指定した理由は「`net/http` のメソッド付きパターンマッチ（1.22 以降）が使えること」であり、1.26.3 はこれを満たす。より新しいバージョンを避ける理由が無いため、環境にあるものを採用した。`mise.toml` をリポジトリにコミットし、バージョンを固定している。

**影響範囲:** なし。標準ライブラリのみを使うため、互換性の懸念は無い。

---

## D-002: 依存方向テストの許可リストに `context` と `sync` を最初から入れた

**計画の記述:** Task 1 では最小の許可リストとし、`context` は Task 19 で追加する

**実際:** 最初から `context` と `sync` を含めた

**根拠:** 許可リストを小刻みに広げても守られる不変条件は変わらず、PR ごとにテストファイルを触る差分ノイズが増えるだけ。`context` はリポジトリインターフェースで必須になることが計画時点で確定しており、`sync` はテストの並行検証で使う。どちらも「外部への依存」ではなく、ドメイン層が外側を知らないという本来の制約には影響しない。

**影響範囲:** 検査の厳密さは変わらない。外部モジュール（ホスト名を含む import）と、自リポジトリの domain 外パッケージは引き続き弾かれる。

## D-003: 依存方向テストを全面的に作り直した（敵対的検証の結果）

**きっかけ:** PR #1 に対する敵対的レビューで、検査に4つの穴が見つかった。

**指摘と対応:**

| # | 指摘 | 深刻度 | 対応 |
|---|---|---|---|
| 1 | `os.ReadDir(".")` がサブディレクトリを走査せず、`internal/domain/training/seed` が無検査になる | 高 | `filepath.WalkDir` で `internal/domain` 配下を再帰的に走査するよう変更 |
| 2 | テスト自身のための許可（`os`, `path/filepath` 等）が本番コードにも適用され、ドメイン層がファイルシステムを触れてしまう | 高 | `productionStdlib` と `testOnlyStdlib` に分離。`_test.go` かどうかで適用を切り替える |
| 3 | 走査対象0件でも成功する。`go test -c` したバイナリを別ディレクトリで実行すると検査が空振りする | 中 | `runtime.Caller(0)` からルートを解決して cwd 依存を排除。走査件数0なら `t.Fatal` |
| 4 | CI が無く、実行が人間の規律に戻っている | 中 | `.github/workflows/ci.yml` を追加（gofmt / vet / test -race） |
| 5 | `strings.Contains(p, "/internal/domain/")` は末尾スラッシュ必須で、`internal/domain` 直下の共有パッケージを誤検出する | 低 | `internal/domain` 自体と `internal/domain/` 配下の両方を許可するよう修正 |
| 7 | `go.mod` にパッチバージョンまで書くと、それ未満の環境で toolchain 自動DLが強制される | 低 | `go 1.26` に変更 |

**指摘6（build constraint 付きファイルも検査される）は対応しない。** `//go:build ignore` のコード生成用ファイルを置いたときに落ちるが、現時点でそうした予定は無く、保守的側（過剰に検出する側）に倒れているため実害が小さい。実際に必要になった時点で除外すればよい。

**検証:** 修正後に同じ攻撃を再現し、次を確認した。

- `internal/domain/training/seed/probe.go` に `database/sql` と `net/http` を置く → 検出して FAIL
- `internal/domain/training/zz_probe.go`（本番コード）に `os` を置く → 検出して FAIL
- `go test -c` したバイナリを `/tmp` で実行 → 3ファイルを検査した上で PASS（空振りしない）

**教訓:** 「テストで守る」と書いた仕組み自体を攻撃していなかった。番人を置いたら、番人が本当に噛みつくかを確かめるところまでが実装。
