## 分割の理由

1タスクあたりのコードを省略せずに書き切るため。1ファイルに詰め込むと後半がプレースホルダに劣化する。

## 順序の理由

**ドメインを先に、インフラを後に。** Onion の要はインフラが差し替え可能であることなので、第4部では Postgres ではなくインメモリ実装でサーバーを通す。ドメインが正しいことを DB 抜きで証明してから Neon に差し替えれば、ドメインのバグと SQL のバグが混ざらない。逆順にすると切り分けが不可能になる。

## 破棄された計画

`00-superseded-kotlin-engine.md` は、エンジンをクライアント（Kotlin）に置く前提で書いたもの。ジムに WiFi があることが分かりオフラインが絶対条件でなくなったため、エンジンをサーバーへ移す判断をして破棄した。ドメインロジックの中身は上記の計画へ引き継いでいる。
