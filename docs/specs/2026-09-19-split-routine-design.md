# 分割法（スプリット）

**日付**：2026-09-19

週の頻度を上げられるようにし、「今日は上半身の日」を表現できるようにする。
`maxFrequencyPerWeek = 4` を外し、筋区分の集合を順に回す。

## 何が問題だったか

### 1. 暦週の山谷は週4で既に出ている

重点種目ありで実シードを回すと、1セッションのセット数が 18〜30 で揺れる。

```
月水金日 重点=bench   18 / 30 / 30 / 30 / 21 / 30 / 30 / 30
月水金土 重点=bench   27 / 30 / 30 / 18 / 27 / 30 / 30 / 18
月火木金 重点=bench   27 / 27 / 30 / 18 / 27 / 27 / 30 / 27
```

暦週の最後のセッションが 18 まで落ちる。残差を「その週の残りセッション数」で
割るので、週の終わりに近づくほど分母が小さくなり、埋めきったあとは出す先が
無くなる。

**「週5で効いてくる」と書いていたが、週4で既に出ていた**（`docs/refactoring.md`
の記述は誤り）。ローリング窓は分割と独立に要る。

### 2. 「今日は上半身の日」を表現する手段が無い

補助種目は週目標の残差が大きい区分から貪欲に埋める。残差は軸が何かを知らない。
結果、脚の日に胸の種目が混ざる。

一見きれいに分かれて見えることがあるが、それは `stalest` が**軸と残差を自動的に
同じ向きに揃えている**ため。最後にやったのが最も古い宣言種目は、その区分が
いちばん枯れている種目でもある。この結合は偶然に近く、出席パターンが変わると崩れる。

```
月水金日 重点なし     44.1/0.0   1.2/29.1  40.2/0.0   0.0/32.1   ← 分離する
月水金日 重点=bench   30.6/0.0   9.3/26.1  35.7/14.4  8.7/20.7   ← 崩れる
```

崩しているのはバリエーションレーン。中1日で独立に回るので、脚の日にベンチの
派生が出る。

### 3. 軸の順序を指定しても解決しない

「宣言種目の並びを周期にする」案を測った。**分離は悪化する。**

```
stalest（いまの回転）      宣言の並びを周期に固定
  44.1 /  0.0               19.5 / 19.2   ← ベンチの日
   1.2 / 29.1               26.1 /  9.3   ← スクワットの日が上体優位
  40.2 /  0.0               22.5 / 12.3
   0.0 / 32.1               17.7 / 17.7
```

軸を手で固定すると `stalest` の結合が切れる。ベンチを週2回に増やすと、
スクワット系の残差が溜まったままベンチの日が来て、ベンチの日に脚の補助が入る。

**その日の性格を決めているのは軸ではなく補助**で、補助は残差しか見ていない。
軸に何かを伝える経路が無い。

もう一つ、本人の運用が決め手になる。「ベンチプレス＋背中」「ベンチプレス＋肩」
という日がある以上、その日に許す区分は**軸の刺激区分より広い**。軸からは導けない。

## 決めたこと

### 型

```go
// program パッケージ
type Split struct {
    name    string
    regions []training.MuscleRegion   // 空なら全区分
}

// SplitCycle は順序付きの周期。同じ Split の繰り返しを許す。
// 空なら分割なし（＝従来の挙動）。
type SplitCycle []Split
```

**「集合の集合」ではなく順序付きの並び。**本人の週は 上・下・上・下・上 で、
上が3日ある。集合の集まりでは表せない。

`Program` は `cycle SplitCycle` と `cycleSetOn training.Date` を持つ。

### プリセット

`seed` が持つ。`DefaultWeeklyTarget` と同じ扱いで、**選んだ時点で展開して
`Program` に保存する**。プリセットの定義を後で変えても既存の設定は動かない。

実シードでの成立を測った（軸候補は BIG3＋チンニング、寄与1.0以上を主働とする）。

| プリセット | 日 | 軸候補 | 補助候補 | 週目標合計 |
|---|---|---|---|---|
| 全身法 | （1つ） | 4 | 29 | 全部 |
| upper/lower | upper | bench, pull_up | 21 | 84.0 |
| | lower | deadlift, squat | 13 | 58.5 |
| PPL | push | bench | 13 | 48.5 |
| | pull | deadlift, pull_up | 11 | 48.0 |
| | legs | deadlift, squat | 12 | 46.0 |
| 5分割 | 胸 | bench | 8 | 19.5 |
| | 背 | deadlift, pull_up | 8 | 33.0 |
| | 肩 | **なし** | 3 | 16.5 |
| | 腕 | **なし** | 5 | 27.5 |
| | 脚 | deadlift, squat | 12 | 46.0 |

### 軸の無い日は軸を空にする

5分割の肩・腕には、BIG3＋チンニングの中に主働を持つ種目が無い。

**その日は軸レーンを空にする。**軸は「伸ばしたい種目を重くやる枠」なので、
伸ばしたい肩種目が無ければその枠は存在しない。0.88 のスクワットを肩の日に
出すより正直。

プリセットを選んだ時点で「肩と腕の日に伸ばしたい種目がありません」と警告する。
**弾かない。**肩のプレスを宣言に足せば軸が入る、というのが本人への案内になる。

**契約が変わる。**いま `Plan` は軸が取れないと error を返し、`PlannedSession.main`
が空になる経路は API にも PWA にも無い。両方に通す。

### 周期の進み方は出席回数

`cycleSetOn` からの `SessionCount() mod len(cycle)`。

履歴に分割を記録しなくて済み、編集した瞬間に先頭へ戻る。当日の記録では動かない
（`Before(date)`、D-116 と同じ性質）。

**直近セッションの軸から逆算する案は採らない。**デッドリフトが脚の日と背中の日の
両方の主働になりうる／軸の無い日で周期がずれる／分割を編集した直後に意味を失う、
の3つで破綻する。

副作用：休みの日にふくらはぎ1セットだけ記録すると周期が1つ進む。現在の
`sessionIndexInWeek` と同じ性質だが、分割では「今日は上の日のはずが下になった」と
目に見える。

### 「主働」は寄与 1.0 以上

`accessory_selector.go` の `primaryContribution` を使う。

**最大値を取る方式は採らない。**デッドリフトは HAMSTRING と ERECTOR がどちらも
1.0 で、`StimulusProfile.Regions()` はソート済みなので argmax は ERECTOR に落ちる。
脊柱起立筋を背中の日に入れた人のデッドリフトが黙って背中の日へ移る。

閾値なら答えは「両方の日の候補」で、`stalest` が決める。D-117 の「頻度は創発する」
と同じ筋。

### どの集合にも属さない区分は毎日活きる

`ABS` / `OBLIQUE`（週目標10）はどのプリセットにも入らない。腹はどの日にやっても
よい部位で、これは欠陥ではなく正規の状態。

**未所属の区分は毎日活きる**とする。全部の集合に書かせると、書き忘れた区分が
永久に埋まらない。

### 残差は割らずに天井を掛ける

```
share(区分) = min(残差, 週目標 ÷ その区分が次の f 回で活きる回数)
```

ローリング窓にすると「今週の残り回数」が定義できない（窓が毎日ずれるので
「残り」が存在しない）。割る代わりに天井にする。

分割が無ければ「活きる回数＝頻度」なので、**ローリング窓の段階で閉じる**。
分割が入ったら周期から数え上げるだけで、窓と分割が独立のまま進められる。

### 窓は `date−6 … date−1`

当日は D-116 で除くので、履歴側は6日ぶん。`date−7` にすると先週の同じ曜日が
窓に残り、同じ曜日に通う人は定常状態で残差がほぼ 0 になり、補助が出なくなる。
黙って壊れるのでテストで固定する。

`query/stats.go` も同じ窓に変える。別々に数えると画面とエンジンがずれる
（`CoverageBetween` のコメントが警告している）。

### バリエーションは分割で止める

重点種目の主働が今日の集合に含まれる日だけ出す。

止めなければ、型が「今日は脚の日」と言いながらベンチの派生が出る。型の意味を
自分で否定することになる。

代償：重点ベンチ＋上下分割なら系統は週3回（上の日が3日あるため）。週3の上下分割
なら週1.5。**ベンチを週3やりたいなら上の日を3つ置く周期を組む**、が正しい答えで、
順序付きの周期ならそれができる。

### 回復判定は分割に優先する

回復は生理で、周期の並びは本人の責任。周期 [上, 腕] を連日で置くと、腕の日の
二頭・三頭が昨日の上の日で回復中になり、補助がほぼ出ない。これは周期の組み方の
問題として扱う。
