# この先の予定（1週ぶんの見込みを見せる）

**日付**：2026-09-27

補助の割り振り（`docs/specs/2026-09-26-accessory-allocation-design.md`）は、
今日を含めて1週ぶんの回をまとめて決め、今日の分だけを確定している。
先の回の分割の日・軸・バリエーション・補助は計算の中に既にある。
これを「この先の予定」として見せる。

## 何を見せるか（見込みであって約束ではない）

先の回は毎日、その日までの記録から作り直す。画面に出すのは
「このまま予定どおりこなした場合の、今日の時点の見込み」で、次のときにずれる。

- 休んだ、別の種目をやった
- 仮定と違う間隔で通った（先の回の日付は頻度から等間隔と仮定している）
- 記録で推定1RMが動いた（先の回の重量）

## 決めたこと

| 論点 | 決定 | 理由 |
|---|---|---|
| 見せる細かさ | 各回の全種目を、重量・セット数・RIR まで | 本人の希望。変わりうることは画面の文で伝える |
| 先の回の呼び方 | 日付を出さず「今日」「次の回」「2回後」… | 計画は日付でなく出席回数で進む（分割も重点種目の一巡も）。仮定の日付を出すと、その日付を守る必要があるように読める。いつ行くかは本人が決める |
| 置き場所 | 「今日」の画面に1行のリンクを置き、専用のページへ | 「今日」はジムで上から消していくキューなので、先の回の種目と見間違えさせない。毎回見るものではないのでタブは増やさない |
| 作り方 | 見込みを返す専用の API と、ドメインの `Forecast` | 今日の計画と見込みが同じ計算を共有し、今日の応答は重くならない |

### 採らなかったもの

- **週の流れ（分割の日と軸）だけを見せる。**本人が重量まで見たい
- **仮定の日付を出す（目安として小さく添えるのも含む）。**月水金で通う人に別の曜日が出てずれて見える。回復の判定に使う内部の仮定を外に出すと、守るべき予定に見える
- **「今日」の画面の下に、たたんだ節として足す。**今日やる分と見間違えやすい
- **新しいタブを足す。**毎回見るものではない
- **画面から、未来の日付で今の `Plan` を呼ぶ。**それまでの回をこなしたことにならず、割り振り器の見込みと別物になる（今日と同じ軸が出る）。日付を出さないので、渡す日付も決められない
- **`GET /api/sessions` の応答に見込みを足す。**ジムで毎回開く今日の応答と、オフラインのキャッシュが、見ないかもしれない先の回の分まで重くなる

## ドメイン：`SessionPlanner.Forecast`

いまの `selectLineup` は先の回まで割り振って回0だけを取り出している。
これを全部の回の並びを返す形に広げ、各回に重量を付けて返す。

```
Forecast(req PlanRequest) ([]PlannedSession, error)   // 回0 = 今日、回1 = 次の回、…
Plan(req) = Forecast(req) の回0                        // 経路を1本にする
```

**各回の中身**

- **軸・バリエーション**：`ProjectHorizon` が決めたもの。役割（重い日・ボリュームの日・派生）も使う。
  予測器はいま役割を外に出していないので、パッケージの中だけで受け取れるようにする
- **補助**：割り振り器が回 k に割り振ったもの
- **重量**：いまの `prescribe` を各回の並びに当てる。推定1RMは**今日の時点**（前日までの記録）、
  評価する日付も今日。42日の鮮度判定と上乗せの判定が今日の計画と同じ基準で動く。
  先の回でやった分による伸びは見込まない。「今日の実力でその回の処方をしたら何kgか」

**直すところ**：いまは今日の空き枠が0だと割り振りをせずに抜ける。`Forecast` では
先の回に枠があるので、今日の枠が0でも割り振りは回す（回0には何も入らない）。

**守ること**

- `Plan` と `Forecast` の回0は必ず一致する（`Plan` を回0の取り出しにするので構造上ずれないが、テストでも固定する）
- 見込みも一日中変わらない（前日までの記録だけから作る）
- 決定性、各回が予算を超えないこと

## API：`GET /api/sessions/forecast?date=YYYY-MM-DD`

- `date` は画面のローカルの今日。`GET /api/sessions` と同じく必須、不正なら 400
- 認証・プログラム未設定の 409・エラーの経路（`respondError`）は `GET /api/sessions` と同じ

```json
{
  "sessions": [
    { "index": 0, "split": "下半身",
      "main": [...], "variation": [...], "accessories": [...] },
    { "index": 1, "split": "上半身", ... }
  ]
}
```

- 1回ぶんの中身（`main` / `variation` / `accessories` と各 `exercise_id`・`weight_kg`・`sets`・`target_rir`）は今日の応答と同じ形
- **日付は返さない。**画面で出さないと決めたのに応答にあれば、いずれ表示される。代わりに `index`（0 が今日）
- `split` はその回の分割の日の名前。分割なしは `null`
- アプリケーション層に `GetForecast` を足す。組み立ては `GetSession` と同じ（週目標の導出、プール、記録、コンディション）

**オフライン**：PWA のキャッシュにも Outbox にも載せない。開いたときに取りにいき、
オフラインでは「オフラインでは見られません」と出す。見込みなので、古いものを見せるより出さないほうが正直。

## 画面

**行き先**：`Route` に `'forecast'` を足す（`'today' | 'history' | 'settings' | 'forecast'`）。
下のタブには出さない。戻るジェスチャーで「今日」に帰る（いまの仕組みのまま）。

**「今日」に足す1行**：今日のリストの下に「この先の予定を見る →」。今日のリストと見た目を分ける。

**予定のページ**

```
この先の予定
─────────────────────────────
今日の時点の見込みです。休んだり、別の種目をやったりすると変わります。
重量は今日の実力での見込みで、当日の記録に合わせて付け直されます。

▼ 今日 ・ 下半身
   スクワット      110kg × 3セット  RIR1
   レッグカール     ─ × 3セット      RIR2
▶ 次の回 ・ 上半身
▶ 2回後 ・ 下半身
```

- 見出しは「今日 / 次の回 / n回後」。分割があれば「・ 日の名前」を添える
- 今日は開いて、先の回はたたんで並べる
- 種目の行は見るだけ。記録用の `ExerciseCard`（タップで記録を開く）は使わず、目標の表示（重量 × セット数・RIR）だけを使い回す
- 重量が付かない種目は今日の画面と同じ表示
- オフライン・通信の失敗は1行の文で出す

**コードの割り方**（`CLAUDE.md`「画面のコードは3層に割る」）
