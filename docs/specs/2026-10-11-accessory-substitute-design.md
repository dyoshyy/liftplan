# 補助の代わりを出す（器具が埋まっていたとき）

**日付**：2026-10-11

器具が埋まっていたとき、いまできるのは「飛ばす」（B6）か「自分で種目を選んで記録する」（B8）だけ。
B8 では何kgでやるかも本人が決める。

「補助を何にするか」と「何kgでやるか」はアプリが答える問い（CLAUDE.md）。埋まっていた日に
それを本人へ押し戻しているのは穴なので、代わりの種目を重量まで付けて差し出す。

## 決めたこと

| 論点 | 決定 | 理由 |
|---|---|---|
| どの枠に出すか | **補助だけ** | 補助はもともと週目標の残差から選んでいるので、同じ判断で「次の候補」が出せる。軸・バリエーションは宣言・系統・強度・上乗せの判定が絡み、代わりを出すと推定1RMの扱いまで波及する |
| 何を基準に選ぶか | **割り振り器と同じ損失**（週の残差） | 判断を1つに保つ。ハムが足りていないならほぼハムの種目が出る。「同じ部位を優先」は割り振り器と別の規則が1つ増える |
| 何を動かさないか | 今日のほかの補助と、先の回の割り振りすべて | 今日の計画は一日中変わらない（D-116）。空いた1枠だけを埋める |
| 代わりも埋まっていたら | もう一度押すと次の候補。出した種目は候補から外していく | 1回で終わると、2台とも埋まっている日に B8 へ戻される |
| 候補が無いとき | 「代わりなし」を返す。画面は「飛ばしてよい」と出す | 損失を減らさない種目を無理に出すと、週目標から遠ざける種目を処方することになる。今日のリストはやめどきを本人が決めるキューなので、飛ばすのは正しい答え |
| 差し替えの保存 | しない。画面の状態だけ。開き直すと元のカードに戻る | 未来のセッションを保存しない設計（README）。記録した分は「今日やったもの」に残るので失われるものは無い。B8 の「選んだ種目」と同じ扱い |
| 記録済みのカード | 1セットでも記録したら「埋まっている」を出さない | 途中までやったならそこでやめればよい（キュー）。途中で差し替えると、同じ枠で2種目を数えることになる |
| オフライン | 「オフラインでは出せません」 | 見込みと同じく、古い答えを見せるより出さないほうが正直（`2026-09-27-session-forecast-design.md`） |

### 採らなかったもの

- **軸・バリエーションの代わり。**本人の判断で補助だけにした。軸が埋まっている日は待つか飛ばす
- **同じ主働筋の種目を優先する。**割り振り器と別の規則が増える。残差で選べば多くの場合同じ部位になる
- **`GET /api/sessions` の応答に代わりの候補を最初から並べる。**毎回開く今日の応答が、ほとんど使わない候補の分だけ重くなり、何番目まで並べるかを決める規則も増える
- **差し替えた結果を保存して、今日の計画そのものを書き換える。**計画は導出するもので保存しない。保存すると予定と実績が食い違う状態が生まれる
- **画面で候補を並べて選ばせる。**選ぶ判断を本人に戻すことになる

## ドメイン（`planning`）

### `SessionPlanner.Substitute`

```go
// Substitute は今日の補助 replace の代わりを1つ導出する。
func (p SessionPlanner) Substitute(
	req PlanRequest, replace exercise.ExerciseID, rejected []exercise.ExerciseID,
) (PlannedSet, bool, error)
```

1. `Forecast` と同じ手順で週ぶんの割り振りを得る（経路を共有する。今日の計画と別の計算にしない）
2. 回0の補助に `replace` が無ければ `ErrNotPlannedAccessory` を返す（軸・バリエーション・予定に無い種目はここで弾く）
3. 回0の補助から `replace` を外した割り振りを **Pinned** にして、もう一度 `Allocate` を回す。候補のプールからは `replace` と `rejected` も外す。回0の空き枠は1つ、先の回の空き枠は0
4. 回0に新しく入った種目があれば、ほかの補助と同じ役割（`accessoryRole`）で `prescribe` して返す。無ければ `ok=false`

重量・セット数・RIR は今日の補助と同じ規則で付く。推定できなければ重量なし（「自分で決める」）で、
これは今日の補助と同じ。

### `AllocationRequest.Pinned`

```go
// Pinned は既に置いてある補助。回ごとに Sessions と同じ並び。nil なら何も置かない。
Pinned [][]exercise.ExerciseID
```

割り振り器はループの前に Pinned を置いたことにする。

- `current`（刺激量）に Pinned のぶんを足す
- `allocated`（回復の判定に使う出来事）に Pinned を入れる
- `chosenSet` に入れる（同じ回に同じ種目を2回置かない）
- `slots` から Pinned の数を引く

先の回の空き枠を0にするのは、呼び出し側（`Substitute`）が `Sessions[k].Slots` を Pinned の数に揃えて行う。
揃えないと、候補が今日ではなく先の回に入り、回0には何も入らないことがある。

**Pinned が nil のときは今と完全に同じ結果になる。**`Forecast` は Pinned を渡さない。

### 失敗の分類

`ErrNotPlannedAccessory` はドメインの番兵。usecase で `apperror.ErrInvalidInput`（400）に分類する。

## API

```
GET /api/sessions/substitute?date=2026-10-11&replace=leg_curl&rejected=seated_leg_curl
```

```json
{"substitute": {"exercise_id": "nordic_curl", "weight_kg": null, "sets": 3, "target_rir": 2, "target_reps": 10}}
```

代わりが無ければ `{"substitute": null}`（200）。

- `date` と `replace` は必須。`rejected` は省略できる（カンマ区切り）
- `replace` が今日の補助に無ければ 400
- 経路は handler → `usecase.GetSubstitute` → `SessionPlanner.Substitute`。組み立ては `GetForecast` と同じ

## 画面

- 補助のカードに「埋まっている」を置く。押すと代わりのカードがその場で差し替わる。見出しに元の種目名を小さく残す（何の代わりかが分かるように）
- 差し替わったカードでもう一度押すと、それまでに出した種目を `rejected` に積んで次の候補を出す
- 代わりが無ければ、カードに「代わりなし。飛ばしてよい」と出す
- 1セットでも記録したカードには出さない
- 3層に割る（`.claude/skills/orchestration-hooks/`）
  - 判断：`substitute.ts`（差し替えの状態から表示するカードを決める・`rejected` を積む・ボタンを出すか）
  - 手順：`useSubstitute.ts`（取得・オフラインの扱い）
  - 描画：`ExerciseCard.tsx` / `Today.tsx`
- `web/scripts/*-check.mjs` に配線の検査を足す

## テスト

先に書いて、期待した理由で赤くなることを確かめる。緑になったら変異を入れて赤くなることを確かめる。

**ドメイン**

- 代わりを出しても、今日のほかの補助と先の回の割り振りが `Forecast` と同じ
- 不足している区分を埋める種目が選ばれる
- 回復中の区分を主働筋にする種目、分割の日に合わない種目、`rejected` の種目、今日すでに出ている種目は出ない
- 損失を減らす候補が無ければ `ok=false`
- `replace` が軸・バリエーション・予定に無い種目なら `ErrNotPlannedAccessory`
- 重量・セット数・RIR が今日の補助と同じ規則で付く（推定できなければ重量なし）
- Pinned が nil なら `Allocate` の結果が変わらない（既存のテストが全部緑のまま）
- `TestSessionPlanner_PlanIsFixedForTheWholeDay` が緑のまま

**API**：400（`replace` 欠落・予定に無い）、200 で null、200 で代わりあり
