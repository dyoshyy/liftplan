# ユーザーストーリー

利用者は1人（本人）。使う場面は「ジムにいる30秒」と「週のどこかで振り返る5分」の2つで、
必要なものがまったく違う。

ジムでは**判断を減らす**ことが価値になる。振り返りでは**判断の材料を出す**ことが価値になる。
同じ画面で両方をやろうとすると、どちらも中途半端になる。

## A. ジムに着いたとき

| | ストーリー | 満たすもの |
|---|---|---|
| A1 | 開いた瞬間に、今日やる種目が並んでいる | `GET /api/sessions` |
| A2 | 各種目の重量が決まっていて、自分で計算しない | 同上 |
| A3 | **前回その種目で何kgを何レップ挙げたかが見える** | **不足** |
| A4 | **種目が日本語で表示される**（`bench` ではなく「ベンチプレス」） | **不足** |
| A5 | 今日が何の日か分かる（標準・高強度・バリエーション） | `role` で満たす |

A3 が無いと、提示された重量を信じる根拠が無い。「今日92.5kg」と言われても、
前回90kgで潰れたのか余裕だったのかで、やることが変わる。

## B. セットをこなす間

| | ストーリー | 満たすもの |
|---|---|---|
| B1 | 1セット終わったら数タップで記録できる | 画面 |
| B2 | 実際のレップが計画と違っても記録できる | `POST /api/set-logs` |
| B3 | **どこまでやったかが、画面を閉じても残る** | **不足**（当日の実績を取れない） |
| B4 | 電波が切れても記録が失われない | 待ち行列（実装済み） |
| B5 | **打ち間違いを直せる** | **不足**（削除の口が無い） |
| B6 | 器具が埋まっていたら順番を飛ばせる | 画面（順序は表示だけ） |

B3 は地味だが実運用では効く。スマホは勝手に閉じる。開き直して
「3セット目まで終わったんだっけ？」となると、記録が信用できなくなる。

B5 が無いのは致命的で、いまは打ち間違いを直す手段がゼロ。同じIDで直そうとすると
409 で弾かれる（D-060）。別IDで正しい値を入れても、間違った記録は残り続けて
推定1RMを汚す。

## C. トレーニング後

| | ストーリー | 満たすもの |
|---|---|---|
| C1 | 体重・睡眠を記録できる | `POST /api/conditions` |
| C2 | 今日こなした総量が分かる | 当日の実績から計算（**不足**） |

## D. 週のどこかで振り返る

| | ストーリー | 満たすもの |
|---|---|---|
| D1 | **過去のセッションを日付順に見られる** | **不足** |
| D2 | **種目ごとの推定1RMの推移が見える** | **不足** |
| D3 | **週目標に対してどれだけ埋まったかが分かる** | **不足** |
| D4 | デロード提案の理由が読め、承認できる | `deload_proposal`（実装済み） |

D2 は「伸びているか」を答える唯一の線。体感は当てにならない。

D3 は**このアプリの中心概念なのに、どこにも表示されていない**。週目標と残差で
補助種目を選んでいるのに、利用者はその存在すら見えない。「なぜ今日この補助種目が
出たのか」が分かるようになる。

## E. 設定

| | ストーリー | 満たすもの |
|---|---|---|
| E1 | **使う種目を選べる** | `PUT /api/program`（画面が無い） |
| E2 | **頻度・週目標を変えられる** | 同上 |
| E3 | トークンを入れ替えられる | 画面 |

E1/E2 は API はあるが画面が無く、curl でしか触れない。「メニュー設定が面倒」を
解決するアプリなのに、設定が一番面倒という状態になっている。

## 足りない API

| 追加するもの | 満たすストーリー |
|---|---|
| `GET /api/exercises` | A4 |
| `GET /api/set-logs?from=&to=` | A3, B3, C2, D1 |
| `DELETE /api/set-logs/{id}` | B5 |
| `GET /api/stats?weeks=N` | D2, D3 |

`GET /api/stats` は推定1RMの推移と週目標の充足を返す読み取り専用の経路で、
`SessionPlanner` を通らない。D-066 で `application/query/` の枠を作ったときに
「来る」と言っていたもの。

## 出さないと決めたもの

- **休憩タイマー**。あると便利だが、RIR は止め時の指示であって秒数ではない。
  タイマーを置くと「2分たったから次」という運用に寄り、設計思想と衝突する
- **カレンダー表示**。未来のセッションは保存しない設計なので、未来の枠は描けない。
  描けるのは過去だけで、それは履歴の一覧で足りる
- **グラフの作り込み**。推移は折れ線1本で足りる。軸や凡例を足すほど、
  ジムで一瞬見るものから遠ざかる
